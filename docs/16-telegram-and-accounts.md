# Telegram и удаление аккаунтов

## Подключение

Один бот обслуживает всю платформу. Токен вводится администратором **на компьютере сервера**:
запустите `telegram-key.bat`, войдите существующим администратором, введите токен скрытым вводом.
Перед запросом логина утилита применяет миграции базы данных, как при запуске сервера;
предварительный запуск сервера не требуется. При ошибке миграции ввод реквизитов не начинается.
Не передавайте его в чат, аргументы команды или `.env`. Повторный запуск заменяет токен;
`telegram-key.bat delete` либо кнопка в настройках удаляет его. `status` проверяет наличие.

Используется Windows DPAPI текущего аккаунта сервера. Файл `telegram.dpapi` лежит рядом с
защищённым ключом Gemini в каталоге экземпляра `%LOCALAPPDATA%/HackathonCommandCenter`.
Каталог зависит от абсолютного APP_DATA_DIR, находится вне данных/бэкапов приложения.
После перезапуска под тем же Windows-аккаунтом токен доступен серверу. Под другой учётной
записью либо вне Windows отправка не работает; открытого резервного хранилища нет.
В интерфейсе отображается только наличие токена, а работоспособность проверяется тестом.
Старые TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID игнорируются транспортом.

Капитан или администратор открывает **Настройки → Telegram** нужного проекта, вводит числовой
ID чата, задаёт маршруты, подтверждает привязку. Бот должен быть добавлен в чат и иметь право
отправки. ID тем вводятся вручную: общего API списка всех тем Telegram нет. Автообнаружение
командами в этой реализации не добавлено. Без тем выбирайте «Общий чат».

Сначала согласуйте отдельный тестовый чат и выберите его для тестового проекта. Кнопка теста
показывает проект, чат и тему перед отправкой. Сообщение называется тестовым и не создаёт
задач/инцидентов/рекомендаций. Рабочий чат настраивается пользователем отдельно.
Реальная доставка требует этой отдельной проверки; автоматические тесты используют имитатор.

## События и получатели

Список получен из действующих вызовов внутренних уведомлений:

| Тип | Внутренние получатели | Упоминания Telegram |
| --- | --- | --- |
| task_assigned | Только новые исполнители | Только новые исполнители |
| task_overdue | Команда проекта и глобальные администраторы | Исполнители просроченной задачи |
| incident_yellow_created | Ответственный, капитаны проекта, глобальные администраторы | Эти получатели |
| incident_red_created | Капитаны проекта, глобальные администраторы | Эти получатели |
| incident_red_confirmed | Команда проекта, глобальные администраторы | Эти получатели |
| incident_resolved | Автор и ответственный | Эти получатели с действующим доступом к проекту |
| ai_recommendation | Команда проекта, глобальные администраторы; только новые записи | Отдельная рекомендация, если включён её маршрут |

Дополнительный маршрут `ai_report` публикует завершённый **запуск целиком**, а не внутреннюю
рекомендацию. Для каждого типа доступны: выключено / общий чат (0) / ID темы (>0).
Неуказанные и выключенные маршруты ничего не отправляют и не используют запасную тему.
Внутренние уведомления сохраняются независимо от настройки Telegram. Один вызов события
создаёт одну доставку со всеми соответствующими упоминаниями, а не доставку на каждого человека.
Исторический журнал mock сохраняется отдельно как preview; старые записи не начинают отправляться.

Username нормализуется в нижний регистр без @, пустая строка/null очищают значение. Сервер
проверяет 5–32 символа `[A-Za-z][A-Za-z0-9_]*`. Повторные упоминания объединяются.
Если username отсутствует/некорректен, выводится имя, а настройки показывают неполноту.
Это не подтверждённая привязка, членство в чате или гарантия прочтения человеком.
Сообщения содержат маркеры событий: 🔴/🟡 для инцидентов, ✅ для закрытия, 🤖 для ИИ,
📌 для назначения, ⏰ для просрочки. Заголовки и подписи выделены жирным, выводы ИИ,
описания ситуации и решения — курсивом; разделы отделены пустыми строками.
Форматирование передаётся через Telegram entities с UTF-16 смещениями, без HTML/Markdown
parse_mode: пользовательский текст остаётся буквальным, упоминания и ссылки кликабельны.

При указании доступного команде HTTP(S) адреса сообщения задач и инцидентов содержат ссылку
с `?project=...&task=...` либо `&incident=...`. Фронтенд проверяет доступ и принадлежность объекта.
Loopback/localhost, адреса с паролем и параметрами не принимаются. Без адреса остаются номера
и названия объектов. Сетевой адрес должен быть доступен с устройств команды.

## Отчёт ИИ

Версия промпта advisor-v2 требует `captain_intervention: required | not_required`.
Любые рекомендации требуют `required`. Без новых рекомендаций допустим `required`, если
в `summary` явно описана остающаяся проблема для решения; иначе — `not_required`.
Сервер отклоняет отсутствие поля, противоречие и посторонние ID; не восстанавливает решение
по догадке. `action_user_ids` перечисляет конкретных исполнителей предлагаемого действия.
Они проверяются по снимку и текущему составу проекта.

Полный короткий отчёт содержит все рекомендации ответа, основания, последствия, действия и
ограничения, включая повторно обнаруженные рекомендации без новых записей в БД. Если новых
рекомендаций нет, публикуется соответствующий итог без упоминаний; это не гарантия отсутствия рисков.
При `required` отмечаются активные капитаны именно этого проекта и конкретные action_user_ids.
Глобальный администратор автоматически капитаном не считается.

Автоматические и ручные анализы подписаны отдельно. Ответы на вопросы не публикуются.
Окончательная ошибка, отсутствие ключа и прерванный анализ публикуются как сбой анализа.
Промежуточное ожидание повторной попытки ещё не является завершённым запуском.
Отдельный маршрут ai_recommendation можно выключить, чтобы не дублировать содержимое отчёта.

## Очередь и диагностика

Изменение проекта, внутреннее уведомление и outbox фиксируются одной транзакцией. Сетевой вызов
выполняет отдельный обработчик после commit, без открытой транзакции на время запроса.
Сохраняются project_id, тип, текст, исходные chat_id/thread_id, состояние, попытки и безопасный код ошибки.

**Смена чата/маршрута влияет только на новые события. Ожидающие и повторяемые записи всегда
сохраняют исходное направление.** Очередь автоматически не удаляется и не переносится.
Перед сохранением другого чата интерфейс показывает предупреждение и запрашивает подтверждение.

Состояния: pending (ожидает), sending, sent, error, uncertain. Старый mock — preview.
Атомарное занятие записи препятствует отправке двумя обработчиками. Аренда — 2 минуты,
сетевой таймаут — 20 секунд. После истечения аренды результат uncertain; автоматического повтора нет.
Для 429/временного отказа — максимум три попытки с задержкой, не меньше retry_after Telegram.
Неверный токен, права бота и недоступная тема сохраняются как понятные ошибки в настройках.
Сырой ответ/исключение провайдера и URL с токеном не сохраняются и не логируются.

Длинный отчёт разбивается по строкам на части до 3800 UTF-16 единиц без потери текста.
Подтверждённые message_id сохраняются после каждой части. При повторе подтверждённые части
не отправляются снова. При потерянном ответе Telegram часть могла быть доставлена: uncertain
и ручное подтверждение риска дубля. Доставка ровно один раз не гарантируется. Восстановление
старого бэкапа также может восстановить старую очередь и привести к повторным отправкам.
Если удаление аккаунта меняет текст уже частично отправляемого сообщения, доставка
приостанавливается. Явно подтверждённый повтор начинает весь обезличенный текст заново;
предыдущие части могут продублироваться. Сообщения в полёте могут уже попасть в Telegram.
История показывает последние 50 доставок конкретного проекта, исходное направление и ошибки.

## Удаление аккаунта

В **Админ → Пользователи** можно изменить/очистить username. Изменение записывается в аудит
без старого/нового username. Полное удаление доступно только администратору для отключённого
аккаунта. Существующая защита последнего активного администратора при деактивации сохраняется.

Предварительный обзор охватывает все проекты, задачи, открытые инциденты и значимые связи.
Пользователь снимается с задач без назначения новых людей. Если удаляется основной исполнитель,
администратор выбирает основного из оставшихся; единственный исполнитель оставляет задачу
неназначенной. Таймеры, сроки, длительности, треки и зависимости не удаляются.

Для каждого проекта с открытыми инцидентами нужно выбрать активного капитана этого проекта.
Если капитана нет, удаление блокируется. Передача отражается в истории инцидента и аудите.
Закрытые инциденты и авторство остаются с исторической ссылкой.

Подтверждение включает версию обзора. Сервер повторно проверяет связи и допустимость замен
под блокировкой записи SQLite; изменившийся обзор требует обновления. Удаление выполняется
одной транзакцией с откатом при ошибке. Исходная строка пользователя действительно удаляется.
Исторические FK и пользовательские цели инцидентов переходят общей технической записи
«Удалённый пользователь», без пароля, username, аватара, ролей и возможности входа.
Эта запись скрыта из управления аккаунтами. Роли, сессии, личные уведомления, блокировки
документов и голоса удаляются; ссылки автора в проектной истории сохраняются.

Сохранённые JSON, известные текстовые копии, снимки ИИ/планирования и outbox редактируются
для удаления точных совпадений текущего имени, логина, username и прежних значений,
известных из административного аудита. История входов обезличивается,
IP для этих записей очищается. Незавершённые ИИ-запросы с пользователем в снимке отменяются,
чтобы ответ от старого снимка не записал данные обратно.

**Границы:** файлы документов, резервные копии, внешние логи и ранее отправленные Telegram
сообщения не очищаются. Свободный текст с неизвестным псевдонимом без точного совпадения
известных значений может остаться. Восстановление старой копии может вернуть аккаунт и личные
данные. Эти ограничения показаны администратору до необратимого подтверждения.

## API и проверка

Все пути ниже имеют префикс `/api/v1`.

| Метод и путь | Права / назначение |
| --- | --- |
| GET /telegram/bot | admin: только состояние, без токена |
| DELETE /telegram/bot/key | admin: удалить общий токен |
| GET, PUT /projects/{id}/telegram | captain своего проекта / admin: настройки, маршруты, подсказки |
| POST /projects/{id}/telegram/test | те же права; confirmed_chat_id и необязательный thread_id; 202 |
| GET /projects/{id}/telegram/deliveries | те же права; последние 50 доставок |
| POST /projects/{id}/telegram/deliveries/{delivery_id}/retry | те же права; accept_duplicate_risk для uncertain |
| PATCH /admin/users/{id} | admin; telegram_username: строка/null, явная очистка |
| GET /admin/users/{id}/deletion-preview | admin; версия, задачи, капитаны, связи, blocked и ограничения |
| DELETE /admin/users/{id} | admin; confirm=true, preview_version, incident_captains, task_primaries |

Миграция `20261029_telegram_accounts` добавляет TelegramSettings, поля outbox и техническую
метку User.deleted_identity, сохраняя существующие mock-записи как preview.

Тесты: test_telegram_delivery.py, test_telegram_ai_reports.py, test_account_deletion.py.
Для UI: `cd backend` → `..\.venv\Scripts\python.exe -m tests.telegram_preview`, затем Vite.
Создаётся отдельная временная БД, провайдеры подставные, доступ к реальному токену отсутствует.
Вход preview-admin / preview-only. Тема 999 имитирует недоступную тему.
После проверки остановите оба сервера.

Поля Bot API сверены с [официальной документацией sendMessage и ResponseParameters](https://core.telegram.org/bots/api#sendmessage).
