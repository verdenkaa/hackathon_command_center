# Песочница: быстрый проход проекта

Песочница находится внизу **Настроек**, в сворачиваемом разделе «Песочница · тестирование и очистка». Раздел и все его API доступны только глобальному администратору. Отдельной вкладки в верхней навигации нет.

## Быстрый старт

1. **Запустить все автопроверки** — проверить семь групп API в отдельной временной SQLite. Можно запускать группы по одной; в карточках и журнале видны результат, причина ошибки и длительность.
2. **Подготовить демо-данные** — создать набор для ручного прохода в выделенном проекте Sandbox. Повторный запуск не дублирует этот набор; уже существовавшие тестовые записи сохраняются.
3. Открыть демо-доску, инциденты или ИИ/аналитику кнопками панели. Для возврата открыть Настройки и развернуть песочницу внизу.
4. Проверить интерфейс по встроенному чек-листу. Фактические логины участников и капитана показаны в разделе аккаунтов, пароль — `sandbox-pass`. Аккаунты с другим паролем или отключённые аккаунты не изменяются: создаётся тестовая замена.
5. В разделе Telegram выбрать демо-проект либо текущий проект и загрузить предполагаемые сообщения. Внешних отправок нет.

## Демо-набор

Создаются 10 задач: все девять стандартных статусов и подзадача; два модуля, исполнители, описания, приоритеты, теги, оценки, просроченный дедлайн, зависимость и чек-лист. Есть активный и приостановленный таймеры, жёлтый блокер и подтверждённая красная эскалация. ИИ включён в режиме мока, первая рекомендация сохранена с контекстом.

Дополнительные сценарии добавляют отдельные события: команда, спринт, просрочка, блокер, цикл таймера и уведомления. Это подготовка ручных примеров, а не автоматическая проверка корректности всей функции.

`integration_failure` выполняет настоящие отрицательные проверки ИИ (выключенный советник, неверный провайдер и отключённый триггер) в изолированной базе вместо прежней записи одной строки в журнал.

## Что проверяется автоматически

| Группа | Проверки |
| --- | --- |
| Вход и права | Реальные login/logout, неверный пароль, видимость проектов, запрет чужого проекта и административных действий |
| Доска и задачи | Модуль, назначения, подзадачи, связи, чек-лист, пользовательская колонка, автостарт/автостоп, конфликт версий и защита стандартных колонок |
| Таймеры | Старт, повторный старт, пауза, продолжение, стоп, права и результат корректировки |
| Инциденты | Жёлтый блокер, комментарий, закрытие, красная эскалация, права капитана и переключения светофора |
| ИИ и уведомления | Промпт/вопрос, предпросмотр и сохранённый контекст, исключение рекомендации, отключённый триггер, внутреннее уведомление и мок Telegram |
| Завершение | Голоса капитана и администратора, запрет записи после завершения, повторное открытие |
| Резервное копирование | Настоящие API backup/restore в отдельном процессе: создание задач и файла, резервная копия, изменение данных, восстановление исходных задач и содержимого файла, integrity_check и foreign_key_check |

Основные группы используют отдельное FastAPI-приложение с собственной фабрикой сессий и временной базой без запуска lifespan. Для backup/restore запускается отдельный скрытый Python-процесс с собственными `APP_DATA_DIR`, `DATABASE_URL` и тестовым администратором: там проходят миграции и реальные API резервного копирования и восстановления, включая файлы документов. Перед этим проверяется, что все пути относятся к созданной временной папке `sandbox-checks/run-...`. Настройки и зависимости работающего приложения не подменяются. Временная папка удаляется после завершения; в основной БД остаётся только отчёт запуска.

Автопроверки не заменяют проход браузером, проверки реальных внешних сервисов или нагрузки. Цикл backup/restore API уже проверяется на отдельном экземпляре приложения; восстановление против рабочей базы из песочницы не выполняется. UI документов исключён из продукта; его сохранённый файловый API участвует только в проверке сохранности архива.

## Очистка

Развернуть «Очистка песочницы», проверить название и ID проекта, ввести **ОЧИСТИТЬ** и нажать кнопку.

- Разрешена очистка только зарегистрированного демо-проекта. Его идентификатор определяется маркером `Project.settings.sandbox`, а не текущим проектом в верхнем списке или названием. Переименование не меняет цель очистки.
- До изменений создаётся проверенная копия SQLite в `data/sandbox-archives/reset-<project_id>-<uuid>.db`. Это полная копия базы до очистки; она предназначена для ручного восстановления администратором, а не автоматического отката рабочего приложения.
- Документы этого тестового проекта, если они были созданы через сохранённый API, перемещаются в соседнюю папку архива. Проверяется принадлежность исходного пути каталогу документов и целевого пути каталогу архивов.
- Удаляются только задачи и дочерние записи демо-проекта, инциденты, модули, колонки, настройки/история ИИ, уведомления, мок-сообщения и его записи аудита. Очищается журнал запусков песочницы; административная запись очистки сохраняется отдельно.
- Восстанавливаются девять стандартных колонок и активное состояние. Общие аккаунты и проектные роли сохраняются. Рабочие проекты, их задачи, файлы и журналы не удаляются.
- При межпроектной связи задач очистка отклоняется. Параллельный запуск сценария/проверки/очистки возвращает `SANDBOX_BUSY`; развёртывание рассчитано на один процесс backend.

## API

Все пути начинаются с `/api/v1/admin/sandbox`.

| Метод и путь | Поведение |
| --- | --- |
| `GET /workspace` | ID, название, состояние, счётчики и фактические тестовые аккаунты; при отсутствии проекта возвращает `project_id: null` |
| `GET /checks` | Каталог семи групп автопроверок |
| `GET /scenarios` | Каталог сценариев подготовки данных |
| `POST /run` | `{"scenario":"full_check"}`, `{"scenario":"check:auth"}` или ключ сценария; неизвестный ключ — `422 UNKNOWN_SCENARIO` без создания проекта |
| `GET /runs` | Последние 100 запусков, включая `checks[]` и `duration_ms` |
| `POST /reset` | `{"project_id":2,"confirm":true}`; без confirm — `422 CONFIRM_REQUIRED`, чужой ID — `409 NOT_SANDBOX`; возвращает путь копии и обновлённую сводку |
| `GET /telegram?project_id=...` | Постоянный журнал предполагаемых отправок выбранного проекта |

Миграция `20261027_sandbox_checks` добавляет к журналу структурированные результаты и длительность, сохраняя прежние записи. Исторический проект Sandbox с существующим журналом получает маркер песочницы. Новые проекты регистрируются сервисом при подготовке данных.
