# ИИ-советник Gemini

Ручные рекомендации, вопросы и решения доступны капитану проекта и администратору.
Историю видят все участники проекта. Ассистент не изменяет задачи автоматически.
Автоанализ включается отдельно; работает в активном проекте после времени начала.
Пропущенные интервалы после перезапуска объединяются в один актуальный анализ.
Завершённые проекты сохраняют доступ к истории.

## Безопасное подключение на Windows

1. Установить зависимости `backend/requirements.txt` в окружение проекта.
2. На компьютере сервера запустить `gemini-key.bat` под той же учётной записью Windows,
   которая запускает платформу. Ввести логин и пароль администратора, затем ключ.
   Пароль и ключ вводятся скрыто. Не передавать ключ в чат, командную строку или `.env`.
3. Ключ сохраняется через Windows DPAPI с привязкой к текущей учётной записи.
   Зашифрованный файл находится в `%LOCALAPPDATA%/HackathonCommandCenter/<instance>/gemini.dpapi`,
   вне каталога данных приложения, резервных копий и экспорта.
4. В настройках администратора выбрать модель и лимиты Google-проекта. Начальные значения:
   `gemini-3.5-flash-lite`, 15 RPM, 500 RPD, 200000 входных TPM. Сверить их в AI Studio.
5. В настройках проекта включить ИИ и, при необходимости, автоанализ.

Повторный запуск `gemini-key.bat` заменяет ключ. `gemini-key.bat delete` удаляет его;
удаление также доступно администратору в интерфейсе. Интерфейс и API никогда не принимают
и не возвращают значение ключа. При сетевом доступе ввод выполняется локально на сервере.
При недоступности DPAPI открытое хранение не используется.

## Обработка запросов

`POST /api/v1/projects/{id}/ai/requests` принимает `kind: analysis | question` и `question`.
Возвращается HTTP 202 и ID сохраняемой заявки. GET этого адреса возвращает историю заявок;
`GET .../requests/{job_id}` — состояние одной заявки. `POST .../ai/run` сохранён как совместимый
адрес ручной постановки заявки, но больше не выдаёт мок за реальный ответ.

Один серверный обработчик выполняет запросы вне транзакции изменения задач. Порядок:
ручной вопрос, ручной анализ, автоанализ. Повторные одинаковые ожидающие заявки объединяются.
Для проекта допускается не более 20 ожидающих заявок, автоматическая заявка — одна.
Зависшие заявки после окончания аренды помечаются прерванными; неизвестный исход сохраняет
израсходованную попытку. Повторы SDK отключены: каждая прикладная попытка учитывается отдельно.

Снимок строится под короткой блокировкой SQLite, содержит серверные аналитику,
планирование, пересечения, зависимости, инциденты и их эскалацию, участников и решения команды.
Сохраняются время, версия и явные неизвестные сведения. Промпты версионированы в
`backend/app/services/advisor_prompts.py`. Командный контекст и вопрос являются данными.
Внутренние рассуждения не запрашиваются, не отображаются и не сохраняются.

Pydantic проверяет JSON и связанные ID по снимку своего проекта. Ошибочный ответ не создаёт
рекомендаций. Сохраняется только безопасный код ошибки, без сырого исключения провайдера.
Для Gemini отправляется облегчённая JSON-схема без числовых границ и ограничений длин:
ограничения вложенных списков могут делать грамматику генерации слишком сложной и вызывать
HTTP 400. Полная строгая Pydantic-схема со всеми ограничениями проверяет полученный ответ
на сервере; облегчение схемы провайдера не ослабляет эту проверку.
Идентичные рекомендации обновляют дату последнего обнаружения, сохраняя решение команды.
Принятая рекомендация не считается выполненной. Старые мок-рекомендации остаются в истории.

`PATCH .../ai/recommendations/{id}` принимает статус `unreviewed | accepted | rejected | deferred`
и необязательный комментарий. Фиксируются автор и время решения. Исключение из следующего
контекста сохраняется через `POST .../recommendations/{id}/exclude`.
Полные отчёты анализов (включая отсутствие новых рекомендаций и ошибки) можно направить
в Telegram. Обязательное решение captain_intervention и правила упоминаний:
[Telegram и аккаунты](16-telegram-and-accounts.md). Ответы на вопросы не публикуются.

## Квоты и диагностика

Все проекты и пользователи платформы используют общий сохраняемый счётчик. Перед каждой
попыткой SQLite атомарно резервирует запрос и входные токены. Дневное окно — полночь
America/Los_Angeles с учётом DST. Минутное окно скользящее, 60 секунд; порог TPM — 90%
суммы использованных и зарезервированных токенов. Резервы неизвестных исходов не возвращаются.

Оценка входа консервативная: UTF-8-байты полного запроса с системными инструкциями и схемой,
плюс запас 10% и 128 токенов. Дополнительные сетевые вызовы count_tokens не выполняются.
Метаданные реального использования сохраняются агрегированно. При нехватке контекста
сначала удаляется старая история из отправляемой копии, с отметкой неполного охвата.
Минимальный запрос сверх лимита завершается до сети; занятое минутное окно откладывает запуск.
Дневной остаток приблизительный; ошибки квоты Google обрабатываются независимо от него.

Общие настройки доступны администратору по `/api/v1/ai/provider`, состояние квоты —
участникам по `/api/v1/projects/{id}/ai/quota`.

## Проверка

Автоматические тесты используют подставной провайдер. `tests/advisor_preview.py` запускает
изолированный UI-стенд с фиктивными данными и ответами, без доступа к реальному хранилищу.
Логин стенда: `preview-admin`, пароль: `preview-only`; стенд слушает только localhost.
Реальные вызовы требуют отдельно согласованного числа попыток и времени проверки.

Официальная документация: [модель](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite),
[структурированные ответы](https://ai.google.dev/gemini-api/docs/structured-output),
[квоты](https://ai.google.dev/gemini-api/docs/rate-limits),
[токены](https://ai.google.dev/gemini-api/docs/tokens).
