# Зафиксированные технические решения

> **Статус документа:** это исходные требования, написанные до разработки, а не описание текущего кода. Что фактически реализовано и где — см. [07-implementation-status.md](07-implementation-status.md); технические спецификации — в [../specifications/](../specifications/README.md).
>
> **Фактическое состояние:** решения о fxTunnel, Autoheal, Uptime Kuma, Google Drive и автоперезапуске приняты, но в прототипе не реализованы. Реализованы восстановление с защитной копией, read-only завершённого проекта и `restart: unless-stopped` в Docker.

Открытых продуктовых вопросов не осталось. Технические решения ниже обязательны для реализации; агент уточняет только безопасные детали конфигурации, не меняя выбранный подход.

| Область | Решение |
| --- | --- |
| Публичный доступ | fxTunnel (`fxtun.ru`), бесплатный HTTP(S)-туннель с исходящим соединением. Свободный поддомен может измениться после остановки; стабильный платный адрес — необязательное улучшение. |
| Автоперезапуск в Docker | `/health` + `restart: unless-stopped` + Autoheal для контейнера приложения. При 5 перезапусках за 10 минут — эскалировать тревогу администратору для ручной диагностики; данные автоматически не восстанавливать. |
| Мониторинг | Uptime Kuma: HTTP(S)-проверка публичного `/health` раз в 60 секунд с 3 повторами и Docker-проверка контейнера; Telegram-уведомление в общий чат. |
| Прямой запуск | Эквивалентный контролируемый перезапуск через службу или планировщик Windows и тот же `/health`; без автоматического восстановления данных. |
| Восстановление данных | Только после явного подтверждения капитана или администратора, с созданием защитной копии текущего состояния. |
