# Hackathon Command Center

Локальный веб-штаб команды хакатона: Kanban с учётом времени, светофор и инциденты, документация, аналитика, ИИ-советник, внутренние уведомления и административная песочница. Один сервис, одна папка данных, запуск на обычном ПК.

## Состояние проекта

Сейчас это **рабочий минимальный прототип**: основные пользовательские сценарии работают и покрыты pytest-тестами, часть интеграций и экранов — заглушки.

## Стек

- Backend: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, SQLite (WAL), Pydantic v2.
- Frontend: React 18, TypeScript, Vite 5, чистый CSS (без UI-библиотек и роутера).
- Данные: папка `data/` (БД, Markdown-документы, резервные копии), общая для Docker и прямого запуска.

## Быстрый старт (Windows)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
Copy-Item .env.example .env   # заполнить APP_FIRST_ADMIN_PASSWORD и APP_SECRET_KEY

# отдельные окна: backend и frontend
.\start.ps1
```

Либо вручную:

```powershell
Set-Location backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# во втором окне
Set-Location frontend
npm install
npm run dev
```

Открыть <http://localhost:5173>. При первом старте создаётся администратор из `APP_FIRST_ADMIN_*` и проект по умолчанию; миграции применяются автоматически при старте.

## Docker

```powershell
Copy-Item .env.example .env
docker compose up --build
```

Приложение доступно на <http://127.0.0.1:8000> и использует ту же папку `data/`, что и прямой запуск.

## Проверка

```powershell
Set-Location backend
..\.venv\Scripts\python.exe -m pytest      # 84 теста
```

`GET /health` возвращает `200`, если приложение отвечает и БД доступна. Проверка записи в папку данных в `/health` пока не выполняется.

## Роли

- `participant` — работа с задачами, таймерами, инцидентами, документами.
- `captain` — дополнительно: корректировка времени, подтверждение красных инцидентов, настройки ИИ, бэкапы и восстановление, голос за завершение проекта.
- `admin` — глобальная роль: пользователи, роли, IP-правила, дедлайн проекта, песочница, редактирование журнала.

Роли складываются; `admin` не привязан к проекту, `participant` и `captain` назначаются на проект.

## Принципы

- Сервер — источник истины: права, переходы, лимиты и таймеры проверяются в API, интерфейс лишь отражает их.
- Все времена в БД — наивный UTC; московское время используется только при отображении и вводе.
- Данные, документы и бэкапы лежат в `data/` и переносятся вместе с `.env`; секреты не попадают в репозиторий и API.
- Интеграции изолированы: сбой Telegram/ИИ не блокирует работу штаба.
