# Frontend

## Компоненты и состояние

`frontend/src/App.tsx` отвечает за вход, выбранный проект, вкладки и навигацию по уведомлениям/ссылкам. `Board.tsx`, `Planning.tsx`, `Incidents.tsx`, `Analytics.tsx`, `Admin.tsx`, `Settings.tsx` реализуют основные экраны. Задачи общие для доски и Ганта; карточки и форматирование используют общие компоненты.

`api.ts` задаёт типы DTO, запросы и события обновления. Используется React state/hooks, без TanStack Query. `navigation.ts` хранит проект, вкладку, открытый объект и фильтры в query-параметрах URL и поддерживает историю браузера. Пользовательский интерфейс не подменяет серверную проверку прав и project_id.

Перетаскивание стрелки A → B в планировании создаёт мягкую связь `after` у B. Общая карточка рядом с описанием показывает зависимости в обоих направлениях: «Выполняется после» у B и «Выполняется до» у A. Меню стрелки позволяет отдельно включить или снять блокировку.

Аналитика читает серверную `summary`, включая `situations`. Argus не имеет отдельной формы вопроса/внешнего провайдера. Экран документов отсутствует.

## Синхронизация

Поток `GET /api/v1/projects/{project_id}/events` сообщает ревизии проекта. После commit данные перечитываются; при переподключении загружается актуальное состояние. Резервный опрос и возврат фокуса/сети поддерживают согласованность при отказе SSE.

Планирование использует проектную revision, операции задач — version там, где она предусмотрена контрактом. 409 не должен приводить к слепой повторной записи. После конфликта обновите состояние и покажите пользователю причину.

## Сетевые ошибки

`request()` отправляет cookie и JSON, разбирает серверный формат ошибок. Отказ fetch и ошибка чтения JSON успешного ответа различаются по типу операции:

| Случай | Код клиента и поведение |
| --- | --- |
| GET/HEAD не прочитан | NETWORK_ERROR; не инициировать рекурсивный project-updated |
| Ответ записи потерян/обрезан | NETWORK_RESULT_UNKNOWN; операция могла сохраниться, отправить project-updated для сверки |

Не повторяйте неидемпотентный запрос автоматически. Пользователь проверяет наличие объекта перед ручным повтором. Успешный HTTP-статус с неполным телом не доказывает неуспех записи.

Ошибка обновления аналитики сохраняет прежний снимок и его время; неизвестные значения не заменяются нулями. Плановые расчёты не дублируются на клиенте.

Начальная ошибка входа/списка проектов показывает возможность повторить загрузку. Необработанный отказ действия показывается общим сообщением, активное сохранение — индикатором; одинаковые одновременные запросы записи объединяются. Автоматического повтора записи после сетевой ошибки нет.

`editor.ts` хранит исходную версию каждого редактируемого поля отдельно от актуальных серверных данных. Нетронутые поля обновляются; изменённые черновики сохраняются в sessionStorage этой вкладки и отправляются с исходной версией. После конфликта пользователь может явно принять серверные значения. Форма создания задачи сохраняет черновик и ключ попытки; исполнители отправляются в одном запросе. Выход из аккаунта удаляет черновики. Таймер увеличивает отображаемое значение локально раз в секунду и сверяется со свежим серверным снимком.

## UI и проверки

Общие стили и примитивы: `index.css`, `ui.tsx`. Текст состояния сопровождает цвет, опасные действия имеют подтверждение. Ввод/отображение времени используют МСК, сервер хранит UTC.

Диалог имеет доступное имя, удерживает и возвращает фокус, обрабатывает Escape и подтверждает закрытие после ввода. Компактная доска показывает основные колонки; все колонки доступны переключателем. Подсказки первого запуска ведут к команде, срокам, трекам и первой задаче. На узком экране план начинается со списка; форму размещения можно заполнить без перетаскивания. Трек можно создать непосредственно из пустого плана. Внешние шрифты не загружаются.

«Мои задачи» показывает личную выборку и количество готовых, активных и затронутых задач; фильтры включают трек, отсутствие исполнителя и препятствия. Аналитика сразу показывает до трёх текущих ситуаций и позволяет выгрузить задачи в CSV и итоги в Markdown. CSV экранирует поля и нейтрализует формулы таблиц. Форма размещения использует исходную ревизию черновика и обновляет нетронутые поля при изменении плана.

`npm test` запускает Node-тесты `frontend/tests/*.test.mjs`; это не полный E2E-набор браузера. `npm run build` проверяет TypeScript и собирает Vite. Браузером отдельно проверяются формы, перетаскивание Ганта, две сессии, сетевой отказ и узкое окно.
