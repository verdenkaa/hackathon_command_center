\# Системные директивы разработки и экономии токенов



\## 1. Правила экономии контекста (Token Optimization)

\- \*\*Ответы:\*\* Будь лаконичен. На вопросы отвечай кратко, без воды, вводных фраз и дифирамбов.

\- \*\*Diffs:\*\* При изменении кода НЕ переписывай файл целиком. Использовать только точечные правки (diff) или изменять только целевую функцию.

\- \*\*Логи:\*\* Если тесты прошли успешно, выводи только краткую строку "ALL TESTS PASSED". Не дублируй логи терминала в чат.



\## 2. Архитектура и качество кода

\- \*\*TDD First:\*\* На каждую новую фичу сначала пиши/обновляй юнит-тест, затем пиши минимально необходимый код для его прохождения.

\- \*\*Типизация:\*\* Строгая типизация Python (Type Hints) и валидация через Pydantic.

\- \*\*Изоляция:\*\* Не читай и не изменяй файлы, не относящиеся к текущей подзадаче.
